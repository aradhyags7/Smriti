## Architectural Rules & Standards
1. **Pydantic v2**: Always use Pydantic v2 syntax (`ConfigDict`, `from_attributes = True`, `Field(...)`).
2. **Field Naming Convention**:
   - Python / Backend / JSON: `snake_case` (e.g., `reaction_time_ms`, `client_attempt_id`, `mood_score`).
   - Flutter / Dart: serialized to `snake_case` in JSON payloads.
3. **Offline-First Synchronization**:
   - The Flutter mobile app generates local UUIDs (`client_attempt_id`, `client_checkin_id`).
   - SQLite holds them with status `PENDING`.
   - When connected, `/api/v1/sync/push` batches multiple game attempts and check-ins.
   - Backend persists them in PostgreSQL and responds with server IDs and sync status (`SYNCED`).
4. **Role-Based Access Control (RBAC)**:
   - Three distinct roles: `PATIENT`, `CAREGIVER`, `ASHA`.
   - ASHA worker access to patient records strictly requires valid consent recorded in the system.
5. **Cognitive Game Metrics (AI Requirement)**:
   - Every game attempt must include: `client_attempt_id`, `patient_id`, `session_id`, `game_type`, `difficulty`, `score` (0-100), `mistakes`, `reaction_time_ms`, and `completion_time_seconds`.
